# Камера дверного глазка

Проект для одного владельца. Meizu Note 9 снимает площадку через глазок. Raspberry Pi 3B хранит видео и обслуживает мобильную веб-страницу. Из Telegram владелец получает уведомления и открывает камеру через мобильный интернет.

## Выбор схемы

Хранение на одном Meizu экономит отдельное устройство, но совмещает архив, запись и обслуживание зрителя на телефоне. Предлагается использовать имеющийся Pi. Его задачи — принять готовое видео, сохранить его и передать браузеру без перекодирования. Телефон и Pi связаны домашним Wi-Fi. Владелец выбрал вход через Telegram по одноразовой ссылке.

## Запись

Пользователь выбирает камеру, видит предварительный кадр и запускает наблюдение. Android-приложение удерживает камеру в службе переднего плана с постоянным уведомлением. Предлагаемый стартовый режим — аппаратный H.264, 720p, 10 кадров/с, без звука. При настройке приложение проверяет поддерживаемые режимы. Для детектора достаточно нескольких уменьшенных кадров в секунду из области глазка. Чувствительность настраивается на месте. Детектор фиксирует движение, личность посетителя владелец определяет по кадру.

Буфер сжатого видео в памяти сохраняет начало прохода с ближайшего предшествующего ключевого кадра. Цель — около трёх секунд до события и пяти секунд после окончания движения. Непрерывное движение продлевает событие с разбиением длинной записи на части. Готовые клипы записываются в локальную очередь, повторная отправка после восстановления Wi-Fi использует прежний идентификатор. Локальные файлы удаляются после подтверждения Pi. Для очереди и архива задаются отдельные лимиты места с вытеснением самых старых завершённых записей и отображением пропусков.

## Просмотр и уведомления

При начале события телефон передаёт кадр и идентификатор. Бот на Pi отправляет в личный чат время, кадр и кнопку запроса доступа. По нажатию бот выдаёт свежую ссылку на событие даже у старого уведомления. Команда открытия камеры работает и без события. В браузере есть прямой эфир, статус связи и история по времени с миниатюрами. Пока ролик загружается, страница показывает его состояние. Для эфира телефон передаёт тот же сжатый поток по запросу зрителя, Pi упаковывает его для браузера. При закрытии страницы или истечении времени ожидания передача эфира прекращается.

## Доступ

В локальной конфигурации Pi владелец задаёт числовой Telegram ID администратора, секрет бота, адрес сайта и отдельный ключ камеры. Бот проверяет тип чата и ID отправителя для команд и нажатий кнопок. При отсутствии ID доступ закрыт. Владелец может обновить ID на Pi. Публичная страница регистрации администратора не требуется.

Одноразовая ссылка действует две минуты. Секрет находится во фрагменте URL. После явного нажатия «Войти» страница передаёт его методом POST по HTTPS и очищает адрес. Сервер атомарно погашает токен, хранит только его хеш и выдаёт защищённую cookie сессии на один час. Повторное открытие ссылки в другом браузере требует нового входа. Все запросы архива, кадров, плейлистов и частей видео проверяют сессию. Выход отзывает сессию. Секреты исключаются из журналов. Загрузка с телефона доступна по отдельному защищённому каналу в локальной сети.

Для удалённого просмотра нужен стабильный публичный адрес HTTPS. Развёртывание допускает обратный прокси при доступном входящем соединении или исходящий туннель с Pi до публичной точки входа. Приложение получает базовый адрес из конфигурации. Выбор точки входа зависит от сети владельца.

## Проверка на оборудовании

Проверить на Meizu длительную запись с погашенным экраном, температуру, резкую смену освещения и короткий проход через кадр. Проверить восстановление очереди при обрыве Wi-Fi, сохранность архива после перезапуска Pi и просмотр через мобильную сеть. Проверить отказ постороннему Telegram ID, параллельное погашение одной ссылки и запросы видео после выхода. Параметры частоты, размера изображения, предзаписи и лимитов хранения — исходные настройки для испытания.
