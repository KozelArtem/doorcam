## Передача работы · 23 ноября 2026

- Рабочая папка `/home/artem/personal/doorcam`, ветка `feature/phone-archive`. В индексе и рабочем дереве есть незакоммиченные изменения. Реализация локальной страницы находится в `android/app/src/main/assets/lan.html` и `lan.js`, сервер в `LanServer.java`, упаковка эфира в `LiveMp4.java`. Не сбрасывать рабочие изменения.
- Локальный эфир сначала зависал на первом кадре. В заголовке блока MP4 `tfdt` исправлена версия формата 64-битной временной метки. Пользователь после установки исправленного APK подтвердил, что эфир идёт нормально. APK лежит в `android/app/build/outputs/apk/debug/app-debug.apk`.
- **Открытая задача — архив на локальной странице.** Пользователь сообщил, что записи не работают. Ещё неизвестно, пуст ли список событий, выдаёт ли плеер ошибку или видео зависает. В headless Chrome с тестовым H.264 и тестовым MP4, сохранённым через `Archive`, прошли запуск и перезапуск эфира, открытие записи и перемотка на 3 секунды. Это проверка браузера и HTTP-сервера. Файл, созданный аппаратным кодировщиком и Android MediaMuxer на Meizu, пока не проверен.
- **ADB настроен.** Использовать Windows `adb.exe` из WSL. Пользователь подключил Meizu по USB и подтвердил запрос на телефоне. `adb.exe devices -l` показал `model:meizu_note9` со статусом `device`. При запуске из песочницы может потребоваться одобрение на доступ к Windows. Перезапуск Windows ADB помог обнаружить телефон. Временный ADB-сервер на порту 5038 остановлен.
- **Блокер при проверке архива.** Сразу после подключения в активном профиле Android `0` команда `adb.exe -d shell pm list packages -f doorcam` вернула пустой список, `pm path by.doorcam.app` не нашла пакет, а `run-as by.doorcam.app ls -lR files/archive` вернула `unknown package`. Журнал `Doorcam`, `MPEG4Writer` и `MediaMuxer` за последние 2000 записей не содержал сообщений. Сначала сверить, на том ли телефоне и в том ли профиле пользователь воспроизводит проблему. Не переустанавливать приложение и не очищать его данные, пока не выяснено, где лежат исходные записи.
- После обнаружения приложения проверить `adb.exe -d shell run-as by.doorcam.app ls -lR files/archive` и `adb.exe -d logcat -d -t 2000 -s Doorcam MPEG4Writer MediaMuxer` после нового события движения. Сопоставить наличие и размер MP4 со списком событий в браузере. Если файлы есть, проверить один проблемный MP4 с помощью `ffprobe` и воспроизвести его по HTTP. В прежнем тесте удалённого WebRTC воспроизводился отдельный таймаут уже на версии из индекса.

Последняя проверка исправленного APK. Все 7 Android-тестов, lint и проверка подписи прошли. Для повторной сборки из папки `android`:

## Текущее направление · 23 ноября 2026

Следующая задача — встроить локальный веб-сервер в Android-приложение для Meizu Note 9. Телефон и устройство зрителя подключаются к одному домашнему Wi‑Fi. ODROID‑C4 пока недоступен: на плате нет Wi‑Fi и под рукой нет кабеля Ethernet.

В текущей версии браузер получает отдельные MP4 через WebRTC и переключает их примерно раз в секунду. На Meizu пользователь наблюдает долгий запуск и прерывания эфира даже после сокращения сегментов и изменений плеера. Причину сетевой задержки отдельно не измеряли.

- [x] Добавить в APK доступ к странице камеры по её IPv4-адресу Wi-Fi. Вход по отдельному паролю, показанному в приложении.
- [x] Отдавать готовые MP4 из существующего архива записей по движению по HTTP с поддержкой Range.
- [x] По запросу зрителя передавать кадры из существующего аппаратного кодировщика H.264 как поток fragmented MP4. Страница подаёт фрагменты в один плеер через Media Source Extensions.
- [ ] На Meizu проверить первый кадр, плавность эфира и перемотку записи по домашнему Wi‑Fi. После этого выбрать исходящее соединение до публичного HTTPS-ретранслятора для просмотра через мобильную сеть. Для удалённого просмотра сохранить вход и управление правами через Telegram.

Локальное воспроизведение начинается по запросу и ожидает следующий ключевой кадр. Существующий пинг-понг WebRTC служит для проверки удалённой связи.

## Исходная схема с Cloudflare и WebRTC

Цель — локальная запись по движению и удалённый просмотр с доступом через Telegram. Спецификация находится в ../specs/2026-11-22-doorcam-design.md. Исполнение по частям с проверкой интеграции.

- [ ] Android, каталог android/. Реализовать настройку адреса Worker, ключа устройства, камеры, лимита архива и чувствительности. Служба переднего плана снимает видео и выявляет движение. Проверить сегментацию, ограничение места и сборку APK.
- [ ] Cloudflare, каталог cloud/. Реализовать бот, выдачу и отзыв прав, OIDC и Mini App, защищённый канал сигнализации в Durable Object. Проверить отказ чужому пользователю, поддельные данные, повторную доставку и потерю соединения.
- [ ] Транспорт и интерфейс, cloud/public/ и локальный JS на телефоне. Клиент WebRTC получает список событий, ролик или последовательность живых MP4-сегментов. Проверить границы сообщений, отсутствие камеры, повтор подключения и смену выбранной записи.
- [ ] Интеграция. Сверить контракты, прогнать тесты, собрать APK, подготовить инструкцию по установке, секретам и настройке webhook. Проверку физической камеры и внешнего аккаунта отметить отдельно.
